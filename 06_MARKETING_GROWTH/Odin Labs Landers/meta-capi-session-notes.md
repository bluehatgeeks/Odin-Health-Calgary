## Architecture: What Is Actually Running

### Pixel Installation
The Meta Pixel is installed in the **GHL funnel Head tracking code** (funnel: "Odin Health Lab Main Site", domain: `odinhealthlab.ca`). All pages in this funnel — including the owen and emma quiz pages — inherit the pixel from this funnel-level setting. There is no pixel init block in `owen.html` or `emma.html`.

**Critical**: Do NOT add a `<!-- Meta Pixel -->` init block to any lander HTML. GHL already injects it. Adding it causes a duplicate pixel error (`[Meta Pixel] - Duplicate Pixel ID: 705890611034328`) and can suppress event firing.

### Quiz Event Tracking
Browser pixel only — no CAPI from the page side. The `trackFbq()` helper fires standard Meta events:

```javascript
// In owen.html and emma.html — DO NOT CHANGE THIS PATTERN
function trackFbq(eventType, eventName, params) {
  var _fbq = (window.parent && typeof window.parent.fbq === 'function')
    ? window.parent.fbq
    : (typeof fbq === 'function' ? fbq : null);
  if (!_fbq) return;
  // source URL passed explicitly to prevent null-domain events in Meta
  var enriched = Object.assign({ source: window.location.href }, params || {});
  _fbq(eventType, eventName, enriched);
}
```

## The Problems We Solved (Chronological)

### Problem 1: Nav/Footer 404 on Live Pages
**Root cause**: Repo was made private (to hide exposed CAPI token) → `cdn.jsdelivr.net/gh/bluehatgeeks/...` returned 404 because jsdelivr only serves public repos.

**Fix**: Remove the hardcoded CAPI token from all HTML files → make repo public again.

**Files changed**: `owen.html`, `emma.html` (removed `sendCAPI()`, `sha256()`, pixel init block, ipify fetch, and all CAPI call sites).

---

### Problem 2: Duplicate Pixel Error
**Symptom**: Console showed `[Meta Pixel] - Duplicate Pixel ID: 705890611034328`.

**Root cause**: Both `owen.html` and `emma.html` had their own `<!-- Meta Pixel -->` init snippet AND the GHL funnel settings also injected the pixel via Head tracking code.

**Fix**: Remove the pixel init block entirely from both HTML files. GHL owns pixel initialization.

**Commit**: `135cb99`

---

### Problem 3: Null Domain — Events Blocked by Meta Traffic Permissions
**Symptom**: Console showed `[Meta pixel] 705890611034328 is unavailable on this website due to it's traffic permission settings`. Meta Events Manager showed `null` domain with 19 blocked events/hour.

**Root cause**: When GHL executes custom code blocks (our quiz JavaScript), the script runs in a context where Meta's pixel cannot read `document.referrer` or `window.location` to determine the source domain. Meta sees the origin as `null` and blocks it because `null` is on the block list.

**Why you can't just allowlist `null`**: Meta's traffic permissions UI rejects `null` as an invalid domain string. You cannot add it to the allow list.

**Fix**: Pass `source: window.location.href` explicitly in every `fbq()` call. When the source URL is provided as a parameter, Meta uses it instead of trying to read the document context. This forces the correct domain (`odinhealthlab.ca`) into the event.

```javascript
// Before (broken — null domain):
_fbq(eventType, eventName, params);

// After (working — explicit domain):
var enriched = Object.assign({ source: window.location.href }, params || {});
_fbq(eventType, eventName, enriched);
```

**Commit**: `d98ba4c`

**Confirmed working**: Meta Pixel Helper showed ViewContent, Lead, AddToCart all Active. Meta Events Manager Test Events showed `View content` Processed from Browser, domain `odinhealthlab.ca`.

---

### Problem 4: CAPI Approach Abandoned
**Why we dropped CAPI from the page**: GHL's webhook-based CAPI integration requires a Contact to exist before it can fire. `ViewContent` fires on first quiz answer — before email capture — so there is no contact yet. GHL skips the CAPI action with status "Skipped: This action requires a Contact and none has been provided."

**Decision**: Browser pixel only for quiz events. CAPI via GHL is viable only for post-lead events (i.e., events that fire after the email form is submitted).

## Key Rules — Do Not Break These

1. **Never add a pixel init block to lander HTML.** GHL injects the pixel. Two inits = duplicate pixel error = events suppressed.
2. **Always pass `source: window.location.href` in `trackFbq()`.** Without it, GHL's execution context produces null-domain events that Meta blocks.
3. **Never hardcode the CAPI access token in HTML files.** Repo is public. Token lives in GHL only.
4. **Do not use `trackCustom` for quiz events.** Meta requires standard events (`track`) for optimization. Custom events cannot be used as optimization signals in ad campaigns.
5. **GHL CAPI webhook requires a contact.** Only configure GHL → Meta CAPI automations for events that fire after lead capture (email submitted).
